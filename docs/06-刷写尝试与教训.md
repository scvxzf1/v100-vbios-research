# V100 VBIOS 物理刷写尝试与芯片恢复记录

**日期**：2026-10-26 凌晨　**主机**：本机　**工作区**：`/path/to/v100-vbios-research`
**结论**：❌ 物理刷写未成功（芯片内容为空）。**已改走"开机内存注入"方案，效果等价、零变砖风险。**

## 一、动机

内存注入方案已验证有效（350 W / 1785 MHz），但**重启即失效**。刷写可换取持久化，此外无任何性能收益——1785 MHz 是电压极限，与固件存放位置无关。

## 二、准备

用户用编程器读出完整 1 MiB 备份：

```
v100_full_dump_20261025.bin   1,048,576 B
sha256 4dd19612fcf2685796a9c8d779fcd23af000eebd04076a28649f42324c3ca439
```

结构核验：6 个镜像位于 `0xA00..0x50A00`，Image0–4 校验和为 0，Image5 为 6（动态日志区，非固定值），`0x50A00–0x100000` 全 `0xFF`。

> **备份完整性**：此前 nvflash `--save` 只得到 330,240 字节（`0x50A00`），而 `--compare` 报 `adapter ROM space = 0xFF600`（即 `0x100000 − 0x0A00`），证明**这颗 flash 是 1 MiB**。因此编程器这份 1 MiB dump 才是**唯一完整备份**。

## 五、nvflash 路线受阻

```
$ nvflash -i 1 --check
Status Register : Restricted or unsupported.
```

读写不对称：`--save` 一直正常，**写被拦在状态寄存器层**。这大概率就是芯片写保护（SRP/BPL）或该 EEPROM 不被 nvflash 支持。

另发现 `--compare` 要求完整尺寸：
```
ERROR: Size difference between file(0x50000) and adapter ROM space (0xFF600)
```

⇒ **nvflash 路线放弃，改编程器。**

## 六、编程器刷写与结果

用户拆下显卡，用 CH341A 连接，尝试写入修改版。

**2026-10-26 00:16 读回结果：**

```
chip_current_0016.bin   1,048,576 B   sha256 f5fb04aa5b882706b9309e88…
非 0xFF 字节数: 0     ← 整个芯片完全空白
```

关键字段全部读到 `0xFFFF` / `0xFFFFFFFF`，6 个镜像的 magic 全为 `FF FF`。

> 注意：空白区（全 `0xFF` 且长度为 256 整数倍）的字节和也对 256 取余为 0，因此**不能用"校验和 = 0"判断镜像完好**——必须以 magic 与内容非空性为准。

### 两种可能，性质不同

| 可能 | 含义 | 判别方法 |
|---|---|---|
| **A. 擦除成功、写入失败** | 固件已不在芯片，**显卡插回不会点亮** | CH341A 能正确识别型号，且读回仍全 `0xFF` |
| **B. 夹子/接触不良** | 读取本身失败，芯片内容可能完好 | 「检测芯片」识别不出型号，或型号与丝印不符 |

**无论哪种，都必须用原厂备份重写一遍。**

## 七、恢复步骤（CH341A）

要写回的文件：

```
firmware/v100_original_1m.bin   1,048,576 B
   （当时另存的文件名为 v100_RESTORE_ORIGINAL_1M.bin，内容与哈希完全相同）
sha256 4dd19612fcf2685796a9c8d779fcd23af000eebd04076a28649f42324c3ca439
```

1. **确认连接**：「检测 / Detect」→ 型号须与芯片丝印一致，容量显示 **1 MiB (1048576)**
2. **先读一次**存成 `chip_before.bin`，记录当前状态（哪怕全 `FF`）
3. **擦除**（Erase）
4. **写入** `firmware/v100_original_1m.bin`（当时名为 `v100_RESTORE_ORIGINAL_1M.bin`），起始地址 `0x000000`，写满 1 MiB
5. **软件校验**（Verify）
6. **独立回读**存成文件，`sha256sum` 必须等于 `4dd19612…`
7. 回读文件中关键字段应为原厂值：

| 偏移 | 期望值 | 含义 |
|---|---|---|
| `0x03348F` / `0x033493` | `0x493E0` (300000) | 功耗 300 W |
| `0x031597` / `0x0315E9` | `0x85FA` | XBAR/SYS 1530 |
| `0x03156E` / `0x0315C0` | `0x0520` | GPC 1312 |
| `0x000A00` | `55 AA` | Image0 魔数 |

⚠️ **供电 3.3V，切勿用 5V**；注意 pin1 方向与夹子接触。

放弃刷写，改为开机 systemd 单元自动注入（详见 [`01-总览与结论.md`](01-总览与结论.md) §六、[`../deploy/README.md`](../deploy/README.md)）。

## 九、教训

1. **`--check` 报 `Restricted or unsupported` 时不应继续**。这是明确的"写不进去"信号，当时应止步于此。
2. **"校验和 = 0"不能证明镜像完好**，全 `0xFF` 的空白区同样满足该条件。判完好必须看 magic 与内容非空。
3. **编程器写入后必须独立回读比哈希**，不能只看软件自报的"Verify 成功"。
4. **备份要在动手之前、并且是完整尺寸**。若当时只有 nvflash 那份 330,240 字节的不完整备份，这次就无法恢复。
