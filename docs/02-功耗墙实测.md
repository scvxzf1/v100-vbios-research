## 3. 镜像结构（88.00.4F.00.09）

| 区间 | 类型 | 大小 | additive checksum |
|---|---|---|---|
| `0x000A00..0x00EE00` | PCIR code `0x00`（Legacy） | 58,368 | 0 |
| `0x00EE00..0x020600` | PCIR code `0x03`（EFI） | 71,680 | 0 |
| `0x020600..0x031400` | NPDS code `0xE0` | 69,120 | 0 |
| `0x031400..0x03E800` | **NPDS code `0xE0`（含时钟/功耗/VFE 表）** | 54,272 | 0 |
| `0x03E800..0x03FA00` | NPDS code `0x70` | 4,608 | 0 |
| `0x03FA00..0x050A00` | NPDS code `0x70` | 69,632 | **140（特殊尾部约定，勿强行归零）** |

文件前 `0x0A00` 字节是 NVGIO flash 描述符区，**不属于 ROM 镜像本身**。

所有表位置均从 NPDS 数据区的 BIT token 指针动态解析得到（`v100_derive.py`），非硬编码。

## 4. 注入点（本方案核心）

### 4.1 接口

```bash
# 格式: 键名=裸二进制，整个 payload 直接跟在 '=' 后面
{ printf 'vbios='; cat payload.bin; } > /proc/driver/nvidia/registry
```

代码路径（`kernel-open/nvidia/nv-procfs.c` 的 close 处理）：

```c
key_value = (char *)nvpp->data;
key_name  = strsep(&key_value, "=");                    // "vbios"
count     = nvpp->off - key_len;                         // '=' 之后全部字节
rm_write_registry_binary(sp, nv, key_name, key_value, count);
```

- 写全局文件时 `nv == NULL` → `regCreateNewRegistryKey(NULL, ...)` → 落在**模块级全局表**，GPU unbind/rebind 后仍在
- 写入缓冲上限 `NV_PROC_WRITE_BUFFER_SIZE = 512 * PAGE_SIZE = 2 MiB`
- `NV_MAX_REGISTRY_KEYS_LENGTH = 512` 只限制键名字符串长度，与数据长度无关

### 4.2 payload 格式（关键，错一点就静默失效）

✅ **正确**：从文件偏移 `0x0A00`（`0x55AA` 处）开始，到最后一个镜像末尾 `0x50A00` 为止，共 **327,680** 字节。
❌ **无效**：带 `0x0A00` 前缀的全量 1 MiB、带前缀的单链裁剪 —— 均被**静默忽略**（版本号都不变）。

```python
payload = open('v100_original.rom','rb').read()[0x0A00:0x50A00]   # 327680 字节
```

### 4.3 生效时机（每个模块生命周期只有一次）

`vbios` 键只在**每个 nvidia 模块生命周期内该 GPU 的第一次 adapter 初始化**时被读取；之后无论再写什么，本模块内都不再读取（改 payload 内容、改大小都没有任何反应）。

复现该窗口（**无需重启**，约 30 秒一轮）：

```bash
rmmod nvidia_drm nvidia_modeset nvidia_uvm nvidia   # 必须先卸干净
echo 1 > /sys/bus/pci/devices/0000:04:00.0/remove    # 把 V100 摘出 PCI 总线
modprobe nvidia                                      # 此时只有 1050 被 probe
{ printf 'vbios='; cat payload.bin; } > /proc/driver/nvidia/registry
echo 1 > /sys/bus/pci/rescan                         # V100 回来并被 probe → 读到我们的 registry
```

已排除的做法：`modprobe nvidia NVreg_ExcludedGpus=0000:04:00.0` 在 580 上**不生效**（V100 照样被初始化）；单纯 `unbind/bind` 在同一模块内也无效。

## 5. 功耗表与生效行

```
BIT P+0x2C → 功耗表 @ 0x3338A
  version 0x30, header_size 39, entry_size 54, count 20
  header+0x0A → tgp_index = 4        ← 本版本是 4，不是 2
```

| 行 | 偏移 | class | 内容 |
|---|---|---|---|
| row0 | `0x333B1` | 10 | min 70 W / 5001 / 5001（哨兵） |
| row1 | `0x333E7` | 4 | 0 / 1001 / 1001（哨兵） |
| row2 | `0x3341D` | 0 | 100 / 300 / 300（**不是 TGP**） |
| **row4** | **`0x33489`** | 4 | **150 / 300 / 300 ← TGP 生效行** |
| row15 | `0x336DB` | 10 | 0 / 5001 / 5001（哨兵） |

行内字段：`+2` = 最小功耗，`+6` = 额定功耗，`+10` = 最大功耗（均为 u32，单位 mW）。

**确证依据**：全镜像中 `150000`（150 W）**只出现一次**，位置正是 `0x3348B` = row4 的 `+2` 字段；而 `nvidia-smi` 上报的 `Min Power Limit` 恰为 150 W。

修改动作：

```python
struct.pack_into('<I', rom, 0x33489+6,  350000)   # rated
struct.pack_into('<I', rom, 0x33489+10, 350000)   # max
# 然后重算数据镜像 [0x31400:0x3E800] 的尾部校验和，使 sum % 256 == 0
```

```
应用前:  88.00.4F.00.09   Current 300.00 W   Min 150 W   Max 300 W   Default 300 W
应用后:  88.00.4F.00.09   Current 350.00 W   Min 150 W   Max 350 W   Default 350 W
恢复后:  88.00.4F.00.09   Current 300.00 W   Min 150 W   Max 300 W   Default 300 W
```

另：`nvidia-smi -i 1 -pl 320` 在应用前被拒（"should be between 100.00 W and 300.00 W"），应用后合法区间变为 **150–350 W**。

## 7. 失败过的做法（避免重走）

| 做法 | 结果 / 原因 |
|---|---|
| 带 `0x0A00` 前缀的全量 1 MiB 作为 payload | 静默忽略，版本号都不变 |
| 以跨版本 `88.00.13.00.02` 作基底 | 只吃版本号与板卡串（`Board Part Number` 变 `N/A`），**功能表退化为默认值**，报 100/300 —— 那个"100 W"即由此而来 |
| 改 row2（`0x3341D` 或 88.00.13 的 `0x32E04`） | 无效。4F 的 TGP 是 row4；88.00.13 的 `tgp_index=2` 指向另一条通道 |
| 改 Image0 `0x5897` 处的 `300000` | 无效。该字节串在 GTX 1050 的 ROM 里完全相同，属**共享代码样板** |
| 改尾部 0x70 镜像 `0x412B0` 一带的 `300000` | 无效。该区域是带 unix 时间戳（`0x5A6986FB` ≈ 2018-01）的 `BBX` 记录/日志区 |
| 在跨版本基底上改时钟字段（GPC 1312→1500、XBAR/SYS 1530→1600） | 无效，同"跨版本"原因 |
| `NVreg_ExcludedGpus` 抢占初始化窗口 | 580 不生效 |
| 同一模块生命周期内第二次写 registry | 无效（只读第一次） |
| 写 4 字节垃圾 payload 期望回退物理 ROM | 不会回退；需 `rmmod`/重启清空 |

3. **频率墙（1530 → 更高）**：仍未突破。已知坐标：
   - Factory clock **A0** 值 @`0x33C20`（flag `0x33C1F`），出厂 **0 kHz**；记录头 `10 06 05 02 05 02` @`0x33C19`
   - VFE 表 @`0x3200E`，base `0x3218F`，150 slot × 24 B，slot13=`1904.47`、slot14=**`1912.0`**（钳位）
   - Base Clock / P-State @`0x3155B`（10 行，stride 41）：GPC 1312/328 @`0x3156E`、XBAR `0x85FA`/382 @`0x31597`、GPC-R1 @`0x315C0`、SYS @`0x315E9`
   - Performance @`0x31455`，entry0 第 3 字段 = 382（×4=1528）
   - **阻塞点**：`nvidia-vbios-vix-editor` 的 `gpc_curve_slot()` 对本镜像报 `FormatError: unreviewed VFE equation kind`（库只审阅 Turing/Ampere/Ada，无 Volta）。而提升 A0 必须配 **VFE 负偏移补偿**，否则是**静默计算错误**（GEMM 出错但不崩溃）。故需先逆向 VFE 方程字节码。
   - 另注：`clkprog` 时钟编程表（23 项，含 **1912 MHz** 上限）位于 Image0 `0x7DE8` 一带，属代码镜像。

## 10. 风险与安全

- **V100 SXM2 为被动散热**，350 W 比 300 W 高 17% 热负荷，长期满载前需确认风道与进风温度。
- 本方案**不写 flash**，全部为内存态；`rmmod` 或重启即完全恢复，**无变砖风险**。
- 但 `v100_original.rom` **务必妥善保存**——它是唯一可信的回退依据；一旦将来真的要刷写，没有这份备份不应动手。
- 若将来改用 nvflash 刷写：`./nvflash -i 1 -6 payload_or_full.rom`，注意 **payload 格式（`0x0A00..0x50A00`）与刷写用完整镜像格式不同**，不要混用。
