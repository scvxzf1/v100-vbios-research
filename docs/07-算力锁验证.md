# Tesla V100-SXM2-16GB 算力锁验证报告

日期：2026-10-25 11:2x CST　主机：本机（`/path/to/v100-vbios-research`）

---

## 结论

**这张 V100 没有任何"算力锁"。**

- 三个项目所针对的 **SM 发射率档位锁（FMLA32 / IMLA4 半速）在 GV100 上根本不存在**——
  实现该锁的整片寄存器窗口在 Volta 上读回 `0xBADF1100`（PRI 违规 / 该芯片未实现），
  驱动也没有实现对应的查询接口（`NV_ERR_NOT_SUPPORTED`）。
- 实测 FP16 张量吞吐：**FP32 累加 104.9 TF/s，FP16 累加 115.3 TF/s，比值 0.91**。
  若存在半速锁，这个比值会是 ~0.50。两者都接近 V100 规格峰值 125 TFLOPS。
- 也没有发现降频、功耗墙下调、PCIe 降级等其它人为限制（详见第 4 节）。

V100 是 Tesla 专业档，本身就按满发射率出厂，所以"买 V100 再解锁"这条路在硬件层面不成立。

## 2. 方法 A：BAR0 寄存器（只读，无驱动依赖）

命令：`sudo python3 bar0_probe.py 0000:04:00.0` → `v100-bar0.json`（⚠️ 该脚本未随仓库发布，见 §6 说明）

### 2.1 Ampere/Ada 的锁寄存器窗口 —— 在 GV100 上整段不存在

| 偏移 | 语义（Ampere/Ada） | V100 实测 |
|---|---|---|
| `0x00820000` | FUSECTRL | `0xBADF1100` |
| `0x008200FC` | FUSE_SS_PLM | `0xBADF1100` |
| `0x008207D8` | **FUSE_SS_FMLA32（锁的核心）** | `0xBADF1100` |
| `0x008207EC` | **FUSE_SS_IMLA4** | `0xBADF1100` |
| `0x0082238xx` | 各 FUSE_SS_* | 全部 `0xBADF1100` |
| `0x00823804` | FEAT_OVR_PLM（权限闸门） | `0xBADF1100` |
| `0x00823818` | FEAT_READOUT_1（有效发射率） | `0xBADF1100` |
| `0x0082381C` | SS0 | `0xBADF1100` |
| `0x00823820` | SS1 | `0xBADF1100` |
| `0x001FA824/A828` | WPR2 low/high | `0xBADF1100` |

> `0xBADFxxxx` 是 NVIDIA PRI 的"该地址在此芯片上无效/不可访问"哨兵值，
> **不是**"值为 0 所以没锁"。正确读法是：窗口不存在 ⇒ 机制不存在。

### 2.2 FECS 块（Turing 走的路径）—— 有效读数也取不到

| 偏移 | 语义 | V100 实测 | TU102 参考（解锁前） |
|---|---|---|---|
| `0x00409650` | FECS FEAT PLM | `0x0000008F` | `0xFFFFFF8F` |
| `0x00409660` | FECS_FEATURE_READOUT | `0x0003F100` | `0x000002F3` |
| `0x00409664` | SS0 | `0x00000010` | `0x00000000` |
| `0x00409668` | 有效 readout | **`0xBADF5040`** | `0x00400080` |
| `0x0040966C` | SS1 | **`0xBADF5040`** | `0x00000000` |

关键是 `0x409668`（有效发射率读出）与 `0x40966c`：在 Turing 上它们给出
"哪几项被降速"的答案，在 V100 上直接是 `0xBADF5040`（不可访问）。
`0x409650` / `0x409664` 虽然能读，但字段语义未确立，
不能按 TU102 的位定义解读（数值也不同）。

## 3. 方法 B：驱动 RM getter

命令：`sudo python3 rm_sm_rates.py <本机 GPU-UUID>`（UUID 用 `nvidia-smi -q -d UUID` 现取；该脚本未随仓库发布）

```
V1 NV2080_CTRL_CMD_GR_GET_SM_ISSUE_RATE_MODIFIER (0x20801230)
   -> status 0x00000056 = NV_ERR_NOT_SUPPORTED ("Call not supported")
```

对照：同一命令在 GTX 1050（GP107 / Pascal）上同样返回 `0x56`。

**解读**：驱动没有为 GV100 实现"读 9 项发射率"这个 control ⇒ 这个概念在 Volta 上不存在。
（若卡上有锁，这里会返回 9 个 `0/1/2` 值。）

> 实现细节坑：RM 的 device object 绑定到**唯一打开的 `/dev/nvidiaN`**，且
> `NV0080_ALLOC_PARAMETERS.deviceId` 要填该卡索引。多卡时如果同时打开了两个设备节点，
> 第二张卡的 alloc 会失败（`0x1b`）。已在本目录脚本中修正。

## 4. 方法 C：真实吞吐（寄存器驻留 mma 探针）

本机没有 CUDA 工具链，因此用 CUDA driver API + 手写 PTX，JIT 出 Volta 的张量指令
`mma.sync.aligned.m8n8k4`（8×8×4 = 256 MAC = 512 ops/warp/指令），
a/b/累加器全程驻留寄存器，**循环内零访存**，与上游 `mma_bench` 同思路。

- 启动几何：`1280` blocks × `256` threads = 10240 warps，每条链 4 条独立累加链
- 迭代：400000 次/launch，10 次取最优
- 数值校验：a=b=1、1 次 mma → 元素 = 4.0 ✅（k=4 累加，说明指令语义正确）

| 变体 | 最好耗时 | 吞吐 | 与 V100 峰值(125 TF/s) |
|---|---:|---:|---:|
| FP16 → **FP32 累加**（锁攻击的目标路径） | 80.0 ms | **104.9 TF/s** | 84% |
| FP16 → FP16 累加（对照，锁不涉及） | 72.7 ms | **115.3 TF/s** | 92% |
| **比值 f32acc / f16acc** | | **0.91** | **有锁应 ≈ 0.50** |

遥测（负载采样，`nvidia-smi -i 1`）：SM 时钟 **1530 MHz（= 该卡最大）**，
功耗 **138–163 W / 300 W 上限**，温度 33–38 °C，`utilization ≈ 100%`。
`Clocks Event Reasons` 中 `SW Power Cap` / `HW Slowdown` / `Sync Boost` 全部 **Not Active**。

**解读**：同一张量管线、满频、功耗只用了一半，跑出 84–92% 峰值；
差的 8–16% 是手写 4 链内核的发射效率，不是卡的限制。
如果存在 FMLA32 类半速锁，FP32 累加路径会是 ~55 TF/s。

> 限制说明：本机 ptxas 只接受这一种 sm_70 张量编码（`m8n8k4`，且 f32 累加形式需 8 个
> 累加寄存器）；`wmma.mma` 与 `m16n8k8/m16n8k16` 在该驱动上被拒绝，
> 所以没能在本机复刻上游「同 cubin、同功耗墙、逐格校验 270336 输出」的完整流程。
> 要拿到最严格的那组数字，需 CUDA 12.x 工具链编译上游 `mma_bench.cu`。

## 5. 其它非"锁"但影响性能的项（已核查）

| 项 | 实测 | 判断 |
|---|---|---|
| 功耗墙 | 300 W（Default 300 / Max 300 / Min 150） | 已在上限，**无法再上调**；不是被人为压低 |
| 时钟 | current = max = 1530 MHz，显存 877 MHz | 满频 |
| 降频原因 | SW Power Cap / HW Slowdown / Thermal / Sync Boost 全 Not Active | 无降频 |
| PCIe | Gen3 ×16（current = max） | **无链路降级**（SXM2 转接卡常见坑，本机不存在） |
| ECC | Enabled | 标准配置，约 3% 带宽代价；要最大化带宽/显存可关，但会改变可靠性语义 |
| `SW Power Capping` 累计计数 | 45,601,491 µs（约 45.6 s，机器累计） | 历史上有过撞功耗墙，属正常 300 W Tesla 满载行为 |

## 7. 一个必须记住的坑

`nvidia-smi` 索引与本机 CUDA ordinal **顺序相反**：

| | nvidia-smi | CUDA / driver API | `/dev/nvidiaN` |
|---|---|---|---|
| GTX 1050 (GP107) | 0 | **1** | nvidia0 |
| Tesla V100 (GV100) | 1 | **0** | nvidia1 |

第一次尝试按 `nvidia-smi` 索引选 CUDA 设备，结果给 Pascal 卡 JIT 了 sm_70 的 PTX，
得到一串 "SM version specified by .target is higher than default SM version assumed" /
"Unexpected instruction types"，误判成"驱动不支持 wmma"。**选卡要用 UUID 或
`cuDeviceGetName` 回读确认，不要用索引。**
