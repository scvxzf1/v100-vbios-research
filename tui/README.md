# V100 快捷操作台（TUI）使用说明

简体中文、键盘驱动的终端操作台，把「改功耗/改频率 → 生成覆盖镜像 → 注入生效 → 存档复现」
压缩成「上下键选择 + 回车 + 键入确认词」。**仅 Linux**，**零第三方依赖**（只用 Python 标准库
`curses`）。

规格与架构见 [`DESIGN.md`](DESIGN.md)；本文只讲怎么用。

---

## ⚠️ 先读这一段：注入会中断图形会话

> **「快速注入」「恢复原厂」「开机持久化」都会卸载内核驱动、操作 PCI 总线，
> 图形会话（GNOME / GDM / SDDM / LightDM）会被中断，界面会关闭，未保存的工作会丢。**

- 注入任务被提交为**独立 systemd 单元**后，本界面立即退出——这不是崩溃，是设计：
  界面自己也会被一起杀掉，假装能监控进度是欺骗性的。
- 请在 **TTY 或 SSH 会话**里操作注入；提交后按屏幕提示用
  `journalctl -u <单元名> -f` 跟踪，或查看 `/var/log/v100-tui/inject-<时间戳>.log`。
- 任何一步失败都会自动回退到原厂状态（重新扫描总线 + 重载驱动 + 拉起显示管理器）。
- 本工具**不写 flash、不改电压**；唯一改动是驱动 registry 里的内存镜像，`rmmod` 或重启即消失。

## 1. 环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 系统 | **仅 Linux**（x86_64） | 非 Linux 直接退出，退出码 `2`，并打印中文原因 |
| Python | 3.8+ | 只用标准库，不需要 `pip install` 任何东西 |
| 终端 | `ncursesw`（宽字符） | 中文按 2 列宽计算；终端过窄会提示「终端过小」而不是乱码 |
| 显卡 | Tesla V100（`10de:1db1`） | 无 V100 时仍可对 ROM 文件做**离线修改** |
| 驱动 | 较新的闭源 NVIDIA 驱动 | 注入依赖 `/proc/driver/nvidia/registry` 接口 |
| 权限 | 注入/持久化/恢复原厂需 **root** | 本工具**不保存、不索取任何密码**，请自行 `sudo` 启动 |

**权限降级矩阵**（非 root 时所有入口都写明原因，不会「按了没反应」）：

| 能力 | 非 root | 说明 |
|---|---|---|
| 快速修改（生成覆盖镜像） | ✅ 可用 | 纯本地字节运算，不触硬件 |
| 快速注入 | ❌ 置灰 | 提示 `需要 root 权限`，并给出 `sudo python3 -m tui` |
| 记录与持久化（档案/历史） | ✅ 可用 | 写入用户配置目录 |
| 开机持久化 安装/卸载 | ❌ 置灰 | 同上 |
| 恢复原厂 | ❌ 置灰 | 同上 |

## 2. 安装与启动

无需安装，仓库自带的 `v100-tui` 就是入口（已带可执行位）：

```bash
./v100-tui              # 进入交互界面
./v100-tui --help       # 中文帮助
./v100-tui --version    # 版本
./v100-tui --once       # 不进界面，打印一份只读状态报告
./v100-tui --no-color   # 单色终端 / 重定向输出

python3 -m tui          # 等价入口（在仓库根目录执行）
sudo ./v100-tui         # 注入、开机持久化、恢复原厂需要 root
```

| 参数 | 作用 |
|---|---|
| `--rom 路径` | 指定基准 VBIOS（完整 dump）。缺省按「驱动 sysfs → `nvidia-smi` 转储 → 指定文件 → 仓库样本」取 |
| `--readonly` | 只读模式：仍可生成覆盖镜像，但改动类入口不动 |
| `--no-color` | 强制单色（语义靠 `✔ ! × ·` 与亮度表达） |
| `--once` | 只打印中文状态报告后退出 |
| `--log-dir 目录` | 内部错误日志目录（缺省写入缓存目录下的 `logs/`） |
| `--version` / `--help` | 版本 / 帮助，退出码 `0` |

**退出码**：`0` 正常；`2` 平台不支持、参数错误或终端不可用；`1` 内部错误（会打印中文提示与日志路径）。

**数据落在哪里**（全部走 XDG 变量，不含任何个人绝对路径）：

| 内容 | 位置 |
|---|---|
| 配置档案 | `$XDG_CONFIG_HOME/v100-tui/profiles/<slug>.json`（缺省 `~/.config/…`） |
| 操作历史 | `$XDG_CONFIG_HOME/v100-tui/history.jsonl`（追加式，只读视图） |
| 覆盖镜像缓存 | `$XDG_CACHE_HOME/v100-tui/payloads/`（可随时删除） |
| 运行期状态 / 日志 | `/run/v100-tui/`、`/var/log/v100-tui/`（root） |

用 `sudo` 启动时，档案与历史会写入**真实登录用户**的目录（按 `SUDO_USER` 解析），不会堆进 `/root`。

## 3. 三种核心能力的操作步骤

### 3.1 快速修改（不触硬件，任何权限都可用）

1. 主菜单选「快速修改」，按提示取基准 ROM；屏幕顶部的来源与 sha256 会告诉你用的是哪一份。
2. 界面先列出**现值**，再让你填**目标值**（功耗上限 150–350 W，五类频率 300–1912 MHz）。
3. `F10` 预览差异（现值 → 目标值），确认后生成覆盖镜像并**回读校验**：
   体积 327,680 字节、sha256、改动字节数、改动是否全部落在唯一数据镜像内、校验和末字节 `old → new`。
4. 结果页可直接 `s` 保存为配置档案、`i` 进入快速注入、`Esc` 返回。

> 字段偏移全部由 `tools/derive_tables.py` 动态推导，换固件版本会自动重定位；
> 推导失败就中止，绝不猜偏移。超过 1785 MHz 会提示「出厂电压下的物理上限」——这只是如实告知，不是承诺。

### 3.2 快速注入（会中断图形会话，需 root）

1. 主菜单选「快速注入」（先要有一份刚生成的覆盖镜像）。
2. **预检页**逐项列出：驱动 registry 是否可写、`/dev/nvidia*` 是否被进程占用、
   覆盖镜像尺寸与 sha256、`systemd-run` 是否可用、是否已有并行任务……任一致命项不通过就**不提交**。
3. **确认页**要求键入完整中文词 `注入`，并显示目标 BDF、固件版本、功耗/频率差异、
   「图形会话将中断」、预计 20–60 秒、失败自动回原厂、覆盖镜像 sha256。
4. 提交成功后界面**立即退出**，终端恢复原状，并打印：

```
完成：注入任务已提交为独立单元 v100-tui-inject-<时间戳>。
图形会话将在数秒后中断，本界面会随之关闭。
请在 TTY 或 SSH 会话查看进度：
`journalctl -u v100-tui-inject-<时间戳> -f`
日志：/var/log/v100-tui/inject-<时间戳>.log
```

5. 下次启动界面时，会用 `/run/v100-tui/last-job.json` 呈现上次结果；
   若上次停在「半摘卡」等危险阶段，启动即弹危险态页，只提供「恢复原厂」与「查看日志」。

实际执行的 9 步（顺序固定，不允许自创）：

```
① 停 lactd → ② 停显示管理器 → ③ 卸载 nvidia_drm/modeset/uvm/nvidia（各 3 次重试）
→ ④ fuser 检查 /dev/nvidia* 无占用 → ⑤ 摘卡（写 remove）→ ⑥ modprobe nvidia
→ ⑦ 写 registry（vbios=<覆盖镜像>）→ ⑧ 重新扫描总线（rescan）→ ⑨ 校验 power.max_limit
恢复：rescan + 重载驱动 + 拉起 lactd 与显示管理器（`trap EXIT` 兜底，幂等）
```

### 3.3 记录与持久化

- **配置档案**：`n` 新建、`Enter` 载入到快速修改、`e` 改名/备注、`x` 删除（键入 `删除`）、`F5` 刷新。
  档案只存语义值（W / MHz），**不存字节偏移**；载入时会按当前固件重新推导。
- **操作历史**：追加式 JSONL，倒序只读展示；`d` 可导出为文本。
- **开机持久化**：安装（键入 `安装`）会调用 `deploy/install.sh`（含 `MANIFEST.sha256` 完整性校验），
  再把档案对应的覆盖镜像放到 `/etc/v100/`；卸载（键入 `卸载`）调用 `deploy/uninstall.sh`。
  卸载后**当前内存里的覆盖仍在生效**，要立刻回原厂请用「恢复原厂」或重启。
- **恢复原厂**：键入 `恢复`，卸载模块并重新加载，丢弃内存覆盖。

危险操作确认词一览（输错不执行，`Esc` 一律取消且无副作用）：

| 操作 | 确认词 |
|---|---|
| 快速注入 | `注入` |
| 安装开机持久化 | `安装` |
| 卸载开机持久化 | `卸载` |
| 恢复原厂 | `恢复` |
| 删除档案 | `删除` |

## 4. 常用按键

| 键 | 作用 |
|---|---|
| `↑` `↓` / `j` `k` | 移动 |
| `←` `→`（配合 `Shift` 为 ±10） | 数值加减 |
| `Enter` | 进入 / 提交输入 |
| `Esc` | 返回上一级；对话框中等同取消 |
| `F5` | 重新读取（只读探测，绝不触发注入） |
| `F10` | 执行当前页主操作（仍需二次确认） |
| `l` / `?` | 日志面板 / 帮助浮层 |
| `q` | 退出（输入状态下输入 `q` 不会退出） |

## 5. 故障排查

| 现象 | 含义与处理 |
|---|---|
| 退出码 `2` + 「本工具仅支持 Linux」 | 平台闸门；本工具只能在 Linux 上运行 |
| 横幅「只读模式（未使用 sudo）」 | 需要 root 的入口已置灰；退出后用 `sudo ./v100-tui` 重开 |
| 「驱动 registry 接口不可用」 | 驱动未加载或版本不支持该接口；先确认 `nvidia-smi` 正常 |
| 「缺少 systemd-run」 | 无法把注入提交为独立任务；本工具**绝不在界面进程内直接卸载驱动**，请装好 systemd |
| `E0202` 字段推导失败 | 该 ROM 结构不受支持；先用 `python3 tools/derive_tables.py <rom>` 单独验证 |
| `E0305` 比率不一致 | 固件的频率比率字段与已知编码不同，默认拒绝写入 |
| `E0504` 持久化不支持该功耗 | 开机脚本尚未参数化到任意功耗，只允许标准 350 W 档案 |
| `E0901` 内部错误 | 打印中文摘要并写出日志（`--log-dir` 可指定目录），请附日志反馈 |
| 终端显示错乱 | 本工具用 `finally` + `termios` 双保险恢复终端；若仍异常，`reset` 或重开终端即可 |

## 6. 已知限制（v0.1.0）

1. **仅 Linux**；不提供 Windows / macOS 支持。
2. **单卡**：不做多卡批量注入或集群编排。
3. **不做** flash 刷写、电压修改、显存频率修改、算力锁开关——要么已被实测证伪，要么风险不可控。
4. **档案导入/导出**（从外部 JSON 导入、导出为文件）未实现，属 v0.2 待办；
   本轮只保证档案的新建/载入/改名/删除与本地存储可靠。
5. **Performance ENTRY0 字段按 4 MHz 对齐**（写入值 = MHz//4），填 1911 实际落 1908，界面会提示。
6. 高于 **1785 MHz** 只提高上报值，实际频率受出厂电压限制（仓库实测结论），界面会给出黄色提示。
7. 主菜单上的 `Esc` 是「取消/返回」语义（设计如此），**退出请用 `q`**；各对话框内的 `Esc` 等于取消。
8. 注入进度**不做实时监控**：提交后界面立即退出（见文首警告），结果在下次启动时呈现。

## 7. 安全说明

- **绝不保存凭据**：不读密码、不把密码喂给 `sudo`、不写 sudoers；需要 root 时只提示你自己 `sudo`。
- **不写 flash、不改电压**：唯一改动是驱动 registry 里的一次性内存镜像，`rmmod` 或重启即消失。
- **失败即回原厂**：单元脚本只有单一失败出口 + `trap EXIT` 兜底 + 状态先行（write-ahead），
  避免把系统停在「半摘卡」状态。
- 风险自负：本工具会卸载内核驱动、操作 PCI 总线；仓库中亦记录过一次**物理刷写导致芯片被擦空**的事故
  （见 [`../docs/06-刷写尝试与教训.md`](../docs/06-刷写尝试与教训.md)）。
